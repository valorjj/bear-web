# M7.6 Tag Pills Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a tag look like a tag while you are writing it.

**Architecture:** `parseTags` already computes each tag's start and end and discards them; this extracts `findTagRanges` and redefines `parseTags` on top of it, so the grammar exists in exactly one place. A ProseMirror plugin then assembles each textblock's text with code masked, runs the same scanner, and emits `Decoration.inline`. The document is never modified.

**Tech Stack:** TypeScript 6, Tiptap 3 / ProseMirror, Tailwind v4, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-08-13-m7-6-tag-pills-design.md`

## Global Constraints

- **The mask character is `\u0000` and must always be written as that four-character escape sequence** — never pasted or typed as a literal NUL byte. A raw NUL looks identical in most editors, but `grep` and `diff` both silently mangle it, and M5 hit this twice. **Before every commit, verify no literal NUL entered any file:** `python3 -c "import pathlib,sys; [print(p) for p in pathlib.Path('.').rglob('*') if p.is_file() and '.git' not in p.parts and b'\x00' in p.read_bytes()]"` must print nothing but binary assets.
- **`parseTags`' observable behaviour must not change.** It decides what the tag index contains; a change there silently reorganises a user's sidebar. Every existing case in `src/data/tags/parseTags.test.ts` must keep passing untouched.
- **Every colour comes from a CSS custom property.** A literal hex or `rgb()` outside `src/styles/tokens.css` fails `npm test` via `scripts/sourceLint.test.ts`.
- **`src/ui/` must import nothing from `src/app/`, `src/data/` or `src/i18n/`;** `src/lib/` likewise plus `src/features/`. Enforced by `scripts/sourceLint.test.ts`.
- **`src/features/editor/markdown.ts` is the only permitted importer of `@tiptap/markdown`.**
- **`lucide-react` is imported only by `src/ui/Icon.tsx`**, enforced by `scripts/sourceLint.test.ts`.
- **Headings keep `--bear-text`.** The accent marks things the user can act on or has acted on.
- **A test that cannot fail is a defect.** Every behavioural assertion must be verified by fault injection — introduce the defect it guards, watch precisely that test fail, restore, report.
- **Verify visually.** Take Playwright screenshots and read `getComputedStyle` rather than inferring appearance from a green suite.
- **All six gates pass before every commit:** `npm test`, `npm run test:e2e`, `npm run lint`, `npm run typecheck`, `npm run format`, `npm run build`.
- Known flakes, both pre-existing and documented: `src/app/AppShell.test.tsx`'s `aria-current` assertion under full-suite load, and `e2e/smoke.spec.ts`'s pane-resize test. Rerun the file alone before concluding anything.

### Task 2: `blockText` — a masked string with a 1:1 position mapping

**Files:**
- Create: `src/features/editor/blockText.ts`, `src/features/editor/blockText.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export const MASK = '\u0000';
  export function maskedBlockText(node: Node): string
  ```
  where `Node` is `@tiptap/pm/model`'s `Node`. The returned string has **exactly one character per document position inside the block**, so a character at index `i` sits at document position `blockPos + 1 + i`.

**Why this is its own task.** The 1:1 mapping is the whole correctness argument for the plugin, and it is easy to get subtly wrong:

- A `hardBreak` contributes **nothing** to `node.textContent` but occupies **one** position. Using `textContent` therefore shifts every later offset. Emit one mask character for it instead — which is also semantically right, since a line break must terminate a tag.
- Any other non-text inline node gets `MASK.repeat(child.nodeSize)`, same reasoning.
- Text carrying the `code` mark is replaced by masks of equal length, so an inline code span cannot contain a tag — matching `parseTags`, which masks backticked spans.
- `MASK` is `\u0000` deliberately: it terminates a tag without permitting one to start. A space would turn `` `x`#work `` into a tag.

```ts
import type { Node } from '@tiptap/pm/model';

/**
 * Stands in for a character a tag may not contain. `\u0000` deliberately, not
 * a space: a space before a `#` satisfies the tag grammar's start rule and
 * would turn `` `x`#work `` into a tag. This is the same convention
 * `src/data/tags/parseTags.ts` uses for masking code in Markdown.
 *
 * Must always be written as this four-character escape sequence — a literal
 * NUL byte looks identical in an editor and is silently mangled by grep and
 * diff.
 */
export const MASK = '\u0000';

/**
 * A textblock's content as a string with EXACTLY one character per document
 * position inside it, so a character at index `i` is at document position
 * `blockPos + 1 + i`.
 *
 * `node.textContent` cannot be used: a `hardBreak` contributes no characters
 * but occupies a position, which shifts every later offset. Non-text inline
 * nodes therefore contribute one mask character per position — which is also
 * correct, since a line break must terminate a tag.
 *
 * Text carrying the `code` mark is masked, so an inline code span cannot hold
 * a tag. That mirrors `parseTags`, which masks backticked spans in Markdown.
 */
export function maskedBlockText(node: Node): string {
  let out = '';
  node.forEach((child) => {
    if (!child.isText || child.text === undefined) {
      out += MASK.repeat(child.nodeSize);
      return;
    }
    const isCode = child.marks.some((mark) => mark.type.name === 'code');
    out += isCode ? MASK.repeat(child.text.length) : child.text;
  });
  return out;
}
```

```ts
import { Extension } from '@tiptap/core';
import { Plugin, PluginKey, type EditorState } from '@tiptap/pm/state';
import { Decoration, DecorationSet } from '@tiptap/pm/view';

import { findTagRanges } from '@/data';

import { maskedBlockText } from './blockText';

/**
 * Renders `#tag` as a pill.
 *
 * A decoration, never a mark: the document is untouched, so no schema,
 * serializer or round-trip path is involved, and a pill can never survive
 * into a note's Markdown. Tags are derived from text; the text stays plain.
 *
 * The consequence is that every round-trip test in this project is blind to
 * whether this plugin runs at all — see `tagPill.test.ts`, which asserts on
 * the decoration set itself.
 */
export function tagDecorations(state: EditorState): Decoration[] {
  const decorations: Decoration[] = [];

  state.doc.descendants((node, pos) => {
    if (node.type.name === 'codeBlock') return false;
    if (!node.isTextblock) return true;

    const text = maskedBlockText(node);
    for (const range of findTagRanges(text)) {
      // maskedBlockText emits one character per document position, so the
      // character at index i sits at pos + 1 + i.
      const from = pos + 1 + range.start;
      const to = pos + 1 + range.end;
      decorations.push(Decoration.inline(from, to, { class: 'bear-tag' }));
    }
    return false;
  });

  return decorations;
}

export const tagPillKey = new PluginKey('tagPill');

export const TagPill = Extension.create({
  name: 'tagPill',

  addProseMirrorPlugins() {
    return [
      new Plugin({
        key: tagPillKey,
        props: {
          decorations(state) {
            return DecorationSet.create(state.doc, tagDecorations(state));
          },
        },
      }),
    ];
  },
});
```

Register `TagPill` in `supportedExtensions` in `src/features/editor/extensions.ts`. **An `Extension` contributes no schema node or mark**, so `computeRecognizedHtmlTags()` and every round-trip suite must be unaffected — Step 5 verifies that.

- **`parseTags` is the deduped name-only view of `findTagRanges`, and the tag
