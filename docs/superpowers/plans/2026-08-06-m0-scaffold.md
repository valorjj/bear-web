# M0 Scaffold Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the bear-web project skeleton — build, styling, linting, unit tests, end-to-end tests, continuous integration, and a live GitHub Pages deployment — so that every later milestone lands on a proven pipeline.

**Architecture:** A single-page React application built by Vite and emitted as a static bundle. Tailwind CSS v4 provides utilities, but every color is read from a CSS custom property defined on `:root[data-theme]`, which is the foundation the M8 theme registry later plugs into. Vitest runs unit and component tests in jsdom; Playwright drives the built bundle in a real browser. GitHub Actions runs both suites on every push and deploys `main` to GitHub Pages.

**Tech Stack:** React 19, TypeScript, Vite 7, Tailwind CSS v4 (`@tailwindcss/vite`), Vitest 3, React Testing Library, Playwright, ESLint 9 (flat config), Prettier 3, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-08-06-bear-web-design.md`

## Global Constraints

- Node 22 LTS. The CI workflow and any `engines` field must both say `22`.
- No backend, no network calls at runtime. The production bundle must work when opened from a static host with no API.
- All durable data belongs in IndexedDB (M1 onward). M0 stores nothing.
- Every color used in application CSS must come from a CSS custom property. No literal hex or `rgb()` values in component code.
- Korean and English are both first-class. No user-facing string is hardcoded in a component after M2; in M0, the only user-facing strings live in `index.html` and the placeholder shell.
- Fonts: Pretendard for UI and body text, JetBrains Mono for code. Both are loaded as self-hosted static assets, never from a third-party CDN.
- No Bear-owned assets. Icons and illustrations are original or open-source with a permissive license.
- Repository root is `/Users/jeongjin/Documents/bear-web`. The git repository is already initialized on branch `main` with one commit.

## Task 2: Tailwind CSS v4 and the design token layer

**Files:**

- Create: `src/styles/tokens.css`
- Modify: `src/styles/index.css`, `vite.config.ts`, `index.html`, `src/app/App.tsx`
- Add: font files under `public/fonts/`

**Interfaces:**

- Consumes: `vite.config.ts` and `src/styles/index.css` from Task 1.
- Produces: raw design tokens on `:root`, all prefixed `--bear-*`: `--bear-bg`, `--bear-surface`, `--bear-sidebar`, `--bear-text`, `--bear-muted`, `--bear-accent`, `--bear-border`, `--bear-font-sans`, `--bear-font-mono`, `--bear-font-size`, `--bear-line-height`, `--bear-line-width`, `--bear-para-spacing`, `--bear-para-indent`. They are overridden under `:root[data-theme='dark']`. Tailwind's theme namespace maps onto them, producing the utilities `bg-bg`, `bg-surface`, `bg-sidebar`, `text-text`, `text-muted`, `text-accent`, and `border-border`. M8's theme registry writes the `--bear-*` names; nothing else in the codebase may.

The prefix is not cosmetic. Tailwind v4's `@theme` block itself declares properties named `--color-*`, so raw tokens under those names would resolve against themselves and collapse.

- [ ] **Step 1: Install Tailwind v4 and its Vite plugin**

```bash
npm install tailwindcss @tailwindcss/vite
```

- [ ] **Step 2: Register the Tailwind plugin**

In `vite.config.ts`, add the import and the plugin. The plugin order matters: Tailwind after React.

```ts
import tailwindcss from '@tailwindcss/vite';
// ...
plugins: [react(), tailwindcss()],
```

- [ ] **Step 3: Write the design tokens**

Create `src/styles/tokens.css`. These values are the seed of the theme system; M8 replaces the hardcoded blocks with generated ones, but the property names stay.

```css
:root {
  --bear-bg: #ffffff;
  --bear-surface: #f7f7f8;
  --bear-sidebar: #eceef3;
  --bear-text: #1c1c1e;
  --bear-muted: #8a8a8e;
  --bear-accent: #d93a3a;
  --bear-border: #e2e2e6;

  --bear-font-sans: 'Pretendard', system-ui, sans-serif;
  --bear-font-mono: 'JetBrains Mono', ui-monospace, monospace;

  /* Editor typography, bound to the M8 preference sliders. */
  --bear-font-size: 16px;
  --bear-line-height: 1.6;
  --bear-line-width: 56em;
  --bear-para-spacing: 0em;
  --bear-para-indent: 0em;
}

:root[data-theme='dark'] {
  --bear-bg: #1c1c1e;
  --bear-surface: #242426;
  --bear-sidebar: #202022;
  --bear-text: #f2f2f7;
  --bear-muted: #8a8a8e;
  --bear-accent: #ff6b6b;
  --bear-border: #3a3a3c;
}
```

- [ ] **Step 4: Wire Tailwind to the tokens**

Replace `src/styles/index.css`. The `@theme inline` block is how Tailwind v4 exposes custom properties as utility classes, so `bg-bg` and `text-muted` resolve to the variables above and automatically follow theme changes.

```css
@import 'tailwindcss';
@import './tokens.css';

@theme inline {
  --color-bg: var(--bear-bg);
  --color-surface: var(--bear-surface);
  --color-sidebar: var(--bear-sidebar);
  --color-text: var(--bear-text);
  --color-muted: var(--bear-muted);
  --color-accent: var(--bear-accent);
  --color-border: var(--bear-border);
  --font-sans: var(--bear-font-sans);
  --font-mono: var(--bear-font-mono);
}

html,
body,
#root {
  height: 100%;
}

body {
  background-color: var(--bear-bg);
  color: var(--bear-text);
  font-family: var(--bear-font-sans);
  -webkit-font-smoothing: antialiased;
}
```

The two layers are deliberately separate. `tokens.css` holds values and swaps
them per theme; `@theme inline` only aliases them into Tailwind's utility
namespace. A theme change rewrites `--bear-*` and every utility follows, with
no rebuild and no re-render.

- [ ] **Step 5: Self-host the fonts**

Download Pretendard and JetBrains Mono as woff2 files into `public/fonts/`. Both are OFL-licensed and may be redistributed; keep their license files alongside.

```bash
mkdir -p public/fonts
```

Place `Pretendard-Regular.woff2`, `Pretendard-SemiBold.woff2`, and `JetBrainsMono-Regular.woff2` in that folder, then append to `src/styles/index.css`:

Note that the `url()` paths below are absolute. Under the GitHub Pages base
path of `/bear-web/`, an absolute `/fonts/...` resolves to the wrong origin
path. Use Vite's base-aware form instead by importing the files, or keep the
fonts in `public/` and reference them relative to the stylesheet as
`../../public/fonts/...` — the simplest correct option is the one shown, but
verify in Task 7 Step 7 that the fonts load on the deployed site, and switch to
relative paths if they 404.

```css
@font-face {
  font-family: 'Pretendard';
  src: url('/fonts/Pretendard-Regular.woff2') format('woff2');
  font-weight: 400;
  font-display: swap;
}

@font-face {
  font-family: 'Pretendard';
  src: url('/fonts/Pretendard-SemiBold.woff2') format('woff2');
  font-weight: 600;
  font-display: swap;
}

@font-face {
  font-family: 'JetBrains Mono';
  src: url('/fonts/JetBrainsMono-Regular.woff2') format('woff2');
  font-weight: 400;
  font-display: swap;
}
```

If the font files are not available at implementation time, skip this step and leave the `@font-face` blocks out — the `system-ui` fallback in `--font-sans` keeps the app readable. Do not substitute a CDN link.

- [ ] **Step 6: Prove the tokens work in both themes**

Update `src/app/App.tsx` to use token-backed utilities and a temporary theme toggle. The toggle is throwaway scaffolding that M8 replaces, but it makes the token layer testable now.

```tsx
import { useState } from 'react';

export default function App() {
  const [dark, setDark] = useState(false);

  const toggle = () => {
    const next = !dark;
    setDark(next);
    document.documentElement.dataset.theme = next ? 'dark' : 'light';
  };

  return (
    <div className="flex h-dvh flex-col items-center justify-center gap-4 bg-bg text-text">
      <h1 className="text-2xl font-semibold">bear-web</h1>
      <button
        type="button"
        onClick={toggle}
        className="rounded border border-border px-3 py-1 text-muted"
      >
        {dark ? 'Light' : 'Dark'}
      </button>
    </div>
  );
}
```

```bash
npm run dev
```

Expected: the page uses the light tokens, and clicking the button switches the background and text to the dark values. If the classes have no effect, the `@theme inline` names and the utility names disagree — `--color-muted` produces `text-muted`, not `text-text-muted`.

```tsx
describe('App', () => {
```

```ts
import { expect, test } from '@playwright/test';

test('the shell renders and the theme toggle works', async ({ page }) => {
  await page.goto('/');

  await expect(page.getByRole('heading', { name: 'bear-web' })).toBeVisible();

  await page.getByRole('button', { name: 'Dark' }).click();
  await expect(page.locator('html')).toHaveAttribute('data-theme', 'dark');

});
```

```yaml
        run: npm run typecheck

      - name: Unit tests
        run: npm test

      - name: Build
        run: npm run build

      - name: Install Playwright browser
        run: npx playwright install --with-deps chromium

      - name: End-to-end tests
```

- [ ] **Step 3: Write the deploy workflow**

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - run: npm ci
      - run: npm run build

      - uses: actions/configure-pages@v5

      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```
